# ReviveCV: Project Overview

ReviveCV is a **Professional Identity Version Control System**. It is not a typical "AI resume generator." Instead, it is built on the premise that a professional career is an evolving timeline of immutable events, and resumes are simply targeted, point-in-time projections (branches) of that history.

This document outlines the core concepts and technical stack driving the project.

---

## 1. Core Concepts & Architecture

The system is designed with enterprise-grade software architecture patterns.

### Domain-Driven Design (DDD)
The project is strictly organized around Bounded Contexts, ensuring clear ownership boundaries and separation of concerns:
- **Career Profile**: The single source of truth for professional history.
- **Branch**: Intent-specific workspaces (e.g., "AI Engineer Persona", "Google SWE Optimization").
- **Session**: The reproducible execution environment where AI optimization and syncing occur.
- **Rendering**: Isolated logic for generating final artifacts (PDF/DOCX).

### Event Sourcing
Instead of mutating a traditional database row when a user learns a new skill, ReviveCV records an immutable **Career Event** (e.g., `SKILL_ADDED`).
- The canonical Career Profile is generated by **replaying** these events deterministically into a Materialized Snapshot.
- This creates a 100% auditable history of the user's career evolution.

### Command Query Responsibility Segregation (CQRS)
The API and data flow separate reads (Queries) from mutations (Commands). Commands represent explicit business actions (e.g., `POST /branches/{id}/sync`) rather than simple CRUD operations (e.g., no `PATCH /branch`).

### Human-in-the-Loop AI Boundary
The AI (LLM) is treated as a tightly scoped **Analysis Capability**, not the brain of the system.
- **AI Reasons, Backend Decides**: The LLM outputs structured facts (e.g., "Add LangChain to skills because the JD requires it"). It *does not* mutate the database.
- **Deterministic Composition**: A deterministic `ResumeCompositionEngine` applies only the AI recommendations that a human explicitly approves.

## 2. Terminology (Ubiquitous Language)

- **Career Profile**: Canonical professional knowledge.
- **Career Event**: Immutable fact describing professional evolution.
- **Branch**: Intent-specific workspace.
- **Session**: Reproducible AI execution.
- **Recommendation**: AI-generated proposal.
- **Approved Change**: User-approved recommendation.
- **Resume Version**: Immutable generated artifact.
- **Promotion**: Selecting the active version.

---

## 3. The Product Workflow

The user experience mirrors modern version control (Git):

1. **Career Event**: A fact is recorded (e.g., learned LangGraph).
2. **Career Timeline (F6)**: Acts as a `git log`, showing how the event mutates the profile and flagging which branches are now `Behind Main`.
3. **Branch Workspace (F1/F2)**: The user opens an affected branch and triggers a sync.
4. **Session Review (F4)**: A "Decision Workspace" resembling a GitHub Pull Request. The user reviews AI recommendations, accepts/rejects them, and executes a final commit: **Create Resume Version**.
5. **Version Explorer (F5)**: A visual DAG (Directed Acyclic Graph) answering *Where did this version come from?* and *What changed?*. The user promotes the best version to be the active artifact.

## 4. Technical Stack

### Frontend (Implemented)
- **Framework**: React 18 with Vite
- **Language**: TypeScript
- **Styling**: Vanilla CSS utilizing Tailwind CSS purely as an implementation layer for a highly cohesive design system.
- **Routing**: React Router (Domain-centric routing: `/career-profile`, `/branches/:id`, `/sessions/:id`, `/evolution`).
- **Icons**: Lucide React
- **Architecture**: Feature-sliced / Domain-sliced directories (`src/domains/branches`, `src/domains/sessions`, etc.) rather than technical slicing (all components in one folder).

### Backend (Planned / Next Phase)
- **Framework**: FastAPI (Python)
- **Architecture**: Event-driven API
- **Data Store**: SQLite with a dedicated EventStore table for immutable career events.
- **AI Integration**: LangChain/LangGraph to orchestrate deterministic LLM interactions (e.g., Qwen3/OpenAI) using strict structured output validation.
- **Document Rendering**: Automated PDF/DOCX generation engines isolated from the core domain logic.

---

## 5. Non-Functional Guarantees
- **Reproducibility**: Every Resume Version is exactly reproducible from its parent version + session data.
- **Auditability**: All domain mutations are auditable via the event log.
- **Explainability**: AI outputs are transparent through explicit provenance (Referenced Events, JD requirements).
- **Determinism**: Event replay reconstructs the Career Profile deterministically.
